# HP-PLAN-010 — Hive Plan Visual Bible: Foundations

Status: PROPOSED

## Directive
This document begins the canonical visual bible for Hive Plan. The product identity is `Obsidian Glass / Electric Signal`: premium, technical, spatial, calm and data-driven. Visual spectacle must never obscure engineering truth.

## Visual principles
1. Truth before decoration.
2. Depth communicates hierarchy.
3. Motion communicates causality/state.
4. Glass is navigation/ambient material, not universal surface.
5. Code, diff, evidence and findings favor solid high-contrast surfaces.
6. 3D is an information layer with semantic 2D mirror.
7. Critical operational colors retain exclusive semantic meaning.
8. Graphics degrade gracefully without functional loss.

## Foundation palette roles
Exact color values remain token implementation candidates until contrast/monitor testing. Semantic roles are frozen conceptually:
- OBSIDIAN_0..5: background/depth hierarchy;
- GLASS_NEUTRAL: translucent utility surfaces;
- SIGNAL_CYAN: focus/data flow/listening;
- SIGNAL_BLUE: active/navigation;
- SIGNAL_VIOLET: reasoning/agent/processing;
- SUCCESS: verified/healthy/completed;
- WARNING: attention/confirmation/degraded;
- DANGER: critical/blocking/error;
- INFO: neutral operational information;
- MUTED: historical/superseded/secondary.
Color alone never carries state.

## Surface hierarchy
S0 VOID: deepest application background.
S1 ENVIRONMENT: atmospheric/3D field.
S2 BASE: primary app regions.
S3 SOLID_CORE: code/diff/evidence/critical data.
S4 GLASS_UTILITY: navigation/filter/toolbar.
S5 FLOATING_GLASS: transient contextual panels.
S6 HOLOGRAPHIC: rare visual/state overlays, never core text surface.

## Typography roles
Use a modern variable sans for UI/body and a high-legibility monospace for code/identifiers. Fonts must be locally cacheable/self-hostable where licensing permits and support Portuguese/technical symbols.
Roles: DISPLAY, H1, H2, H3, BODY, BODY_DENSE, LABEL, CAPTION, METRIC, CODE, IDENTIFIER.
Use tabular numerals for telemetry/cost/timing.

## Spatial scale
Adopt tokenized spacing based on a 4px base unit with a bounded scale. Dense engineering panels may use compact spacing but must preserve touch/keyboard usability.

## Shape language
- restrained rounded corners, not bubble UI;
- tighter radius on dense/technical panels;
- larger radius on ambient/voice/floating surfaces;
- borders are subtle material boundaries;
- critical state may sharpen contrast rather than increase glow.

## Depth
Depth levels D0..D5 combine surface luminance, border, shadow, blur and spatial offset. Avoid stacking multiple strong shadows/blurs.

## Glass policy
Glass requires sufficient backdrop separation and contrast. Text-heavy/code/evidence surfaces do not use translucent backgrounds when it harms legibility. Blur intensity is graphics-profile aware.

## Iconography
Consistent outline/duotone-capable engineering icon system. Icons must have text/tooltip/accessibility names. Operational states use icon + text + optional color/pattern.

## Density modes
COMFORTABLE, DEFAULT, DENSE. Density changes spacing and information packing, not semantic content.

## STOP CONDITION
Foundations freeze only after token implementation, contrast validation, representative cockpit/chat/review prototypes and reduced-graphics comparison.
