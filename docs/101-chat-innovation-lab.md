# HP-PLAN-010 — Engineering Chat Innovation Lab

Status: PROPOSED / TRIAL CANDIDATES

## Purpose
Explore differentiated chat capabilities without silently expanding V1 scope. Every concept must pass utility, complexity, security, performance and operator-value evaluation before adoption.

## Candidate innovations

### Context Lens
A small live indicator shows which canonical sources, memories, files and agents currently influence the answer. Expanding it reveals provenance without cluttering the response.

### Evidence Heatmap
Visually mark which response claims are strongly evidenced, derived, uncertain or awaiting verification. This is not model self-confidence; it is evidence coverage.

### Conversational Time Travel
Select an earlier checkpoint/commit and ask questions against that historical project state. Historical mode is unmistakably labeled and cannot silently mutate current canonical state.

### Architecture Lens
Any architecture answer can open an explorable graph linking components to ADRs, files, tests, risks and current implementation status.

### Voice Command Radar
During hands-free mode, display bounded commands currently safe/available in context rather than requiring memorization.

### Decision Diff
When a proposed decision changes, show semantic differences between previous and current proposal: scope, architecture, cost, risk and affected Work Orders.

### Answer-to-Artifact
Selected response blocks can become a governed ADR/WO/checkpoint proposal while preserving source links and exact originating conversation range.

### Failure Memory Flash
When a proposed implementation resembles a verified prior failure, surface a compact warning and required prevention test before Work Order compilation.

### Project Pulse
A compact ambient strip summarizes blockers, active Work Orders, review status, cost anomalies, stale context and system health while chatting.

### Visual Workspace Memory
The system remembers operator layout/focus preferences separately from engineering truth: opened panels, preferred graph density, voice verbosity and visualization mode.

## Adoption gate
A candidate moves from TRIAL only if it improves verified task outcome, speed, comprehension or error prevention without unacceptable complexity, privacy, accessibility or resource cost.

## Explicit non-goal
Do not turn the chat into a noisy sci-fi HUD. Visual richness is subordinate to engineering comprehension and truthful state.
